# D65 — Every generation call states a ceiling, in proportion to what the model was given

**Date.** 2026-11-13. **Issue.** [#221](https://github.com/ensera-ai/taisce/issues/221).

**Why it was open.** A generation request stated no limit on what the model may write back unless
the operator set one. The text sent to a model is somebody else's, so a message that asks for a
long answer got one, at the operator's expense, up to whatever the provider allows. D46 counted
what was spent and refused a cut reply whole, and deliberately set no default: a ceiling of 4,096
tokens had been built and withdrawn, because a model that reasons before answering returned nothing
under a small ceiling and the corpus could not be run against it to choose a larger one.

**What is protected, and from whom.** The operator's bill, from whoever writes the text a model
reads. And, against the remedy: a turn that asserts a great deal, from a ceiling that would refuse
its reply.

**What was measured.** `deepseek-flash`, 2026-11-13, completion tokens as the provider counted them.

| Prompt | Given | Wrote back |
|---|---|---|
| Extraction, the regression corpus (19 cases, 3 attempts) | messages of 23 to 212 bytes | at most 856 tokens |
| Extraction, one claim a sentence | 592 bytes, 20 claims | 2,707 |
| | 2,399 bytes, 80 claims | 8,642 |
| | 7,228 bytes, 240 claims | 24,753 |
| Report | 4 facts, 226 bytes | 1,242 |
| | 30 facts, 1,744 bytes | 1,368 |
| | 120 facts, 6,978 bytes | 3,532 |
| Compaction | 774 characters | 138 |
| | 7,865 characters | 1,374 |
| | 52,848 characters | 872 |

The second block is what decided the shape. A full reply to a dense message is between 3.4 and 4.6
tokens for each byte of the message, with every one of its claims extracted. The ceiling that was
withdrawn, 4,096, would have cut the reply to the 80-sentence message and refused that turn whole.

**Decided.**
- **A ceiling is a base plus an amount for each byte the model was given.** A short message that
  asks for a long answer is held to a short one. A long message is allowed a long reply, and
  whoever sent it is bounded by what they sent.
- **The figures live in each prompt file's `model_contract`**, beside the temperature, and a prompt
  file that states none does not load. Extraction: 2,048 and 8 a byte. Report: 4,096 and 1.
  Compaction: 2,048 and one half. Each is about twice what was measured, so that the ceiling is met
  by a reply that has gone wrong and not by one that is merely full.
- **The operator's setting replaces the prompt's figure** on every call. It exists for the model
  the default does not suit.

**Rejected: one fixed number of tokens per prompt.** The issue's first option, and what was built
before. Any number low enough to bound a hostile short message refuses the reply to a full one;
the table above is the measurement.

**Rejected: no default, as D46 left it.** It leaves the bound to the provider, and the operator who
has not read this far pays for what somebody else asked a model to write.

**Rejected: a ceiling in proportion to the prompt's tokens as the provider counts them.** It is the
truer measure, and it is known only after the reply. The bytes of the input are known before the
request is sent.

**Rejected: a spend bound per project per day.** Larger, and a different control: it bounds a total
and not a call. The counters that would say what normal is exist now; nothing has asked for it.

**What it does not cover.**
- **A model that reasons before it answers.** It spends the allowance on reasoning and may be cut
  where a model that does not would not be. The refusal says so and names the setting. No such
  model was measured here.
- **Any model but one.** The figures are from `deepseek-flash`. The other model the documentation
  names, Qwen served with thinking off on a rented card, was not run
  ([#280](https://github.com/ensera-ai/taisce/issues/280)). A tokenizer that spends more tokens on
  the same reply narrows the margin.
- **A long hostile message.** A message of 64 KiB is allowed a reply of about half a million
  tokens, which is beyond what a provider grants. What bounds it is the provider, as before; what
  the sender can make an operator spend is in proportion to what they sent.
- **How many times a turn is retried.** A reply that is cut is a failed attempt, and a turn is
  attempted up to six times.

**Proof.**
- `TestAPromptFileThatStatesNoCeilingDoesNotLoad` — the three files that ship state one, and five
  ways of not stating one are refused.
- `TestEveryGenerationRequestStatesACeilingAndEveryCallIsCounted` — every one of the three calls
  carries `max_tokens`, and the operator's number replaces the prompt's.
- `TestAReplyIsAllowedInProportionToWhatWasSent` — a one-line message that asks for ten thousand
  words is allowed little more than an empty one; 300 sentences are allowed more than three times as
  much; the allowance grows evenly with the input.
- `TestAReplyThatWasCutIsRefusedWholeAndStillCounted` — cut by the operator's ceiling, by the
  prompt's allowance, or by the provider below either: refused whole, counted, and told apart.
- `TestTheExtractionCorpus`, run again under the default on 2026-11-13: 19 of 19, 57 calls, none
  cut. It now logs the largest reply of each case, and fails if any reply is cut.

**Undo cost.** Low. Three numbers in three files and one function. The prompt files change, so the
extraction and report identities change with them, as they do on any prompt edit.

**Impact.**
- *Cost.* What a call may spend is bounded before it is sent, by default.
- *Operations.* A deployment on a reasoning model that set no ceiling will see replies cut after
  upgrading, loudly, until it sets one.
