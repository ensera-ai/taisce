# D43 — A decision is a file of its own, named for its number and nothing else

**Date.** 2026-11-11. **Issue.** [#232](https://github.com/ensera-ai/taisce/issues/232).

**Why it was open.** Every decision was appended to the end of one file. Two pull requests that each
recorded a decision therefore changed the same lines, and the second could not merge until somebody
had merged it with the first by hand, pushed, and waited for a build. Measured on 2026-11-11, landing
six pull requests of which five added an entry: every one after the first conflicted in that file and
nowhere else that mattered. Each resolution was mechanical — keep both entries, in number order — and
each cost a full build, about nine minutes, for changes that did not overlap. One resolution was
pushed with its conflict markers still in it, which is what a mechanical step done by hand five times
in a row produces. The file had also reached 2,500 lines, read in full by anyone following a citation
to one entry.

**Decided.**
- **Each decision is `docs/decisions/D<n>.md`.** Forty-two entries were moved with their text
  unchanged apart from the heading level, checked by a digest of every entry before and after.
- **The name is the number and nothing else.** Two pull requests that record different decisions add
  different files and do not conflict. Two that take the same number add the same file, which git
  reports before either merges. That is the collision the single file was good for, and it is the
  only one kept.
- **`docs/01-decisions.md` stays at its path and holds no entry.** The project's rules and other
  documents cite that path (D8), so it remains, as the page that says how the register works and
  where a decision is. The build refuses an entry appended to it.
- **There is no committed index.** `make decisions` reads one from the files' own headings. A list
  with a line per decision would be one file every such pull request has to change — the same
  conflict, moved.
- **The documentation build keeps the whole directory off the site by naming the directory**, not
  each file in it, for the same reason. A kept directory holding no document is refused, as a kept
  file that does not exist already was.
- **The build checks what the register asks of an entry**: a heading whose number matches its file,
  a date, why it was open, what was decided, what was rejected, the undo cost and the impact. The
  register has always said an entry without its alternatives is not finished; nothing held it to that.

**Rejected: a file per decision, named by number and title.** The directory listing would read as an
index, which a list of `D1.md` to `D43.md` does not. But two pull requests taking the same number
would no longer conflict, so a duplicate would be caught by a test — on `main`, after the second had
merged. Numbers have collided here before. A listing is one command; a register with two D40s is a
repair.

**Rejected: keeping one file and adding a merge queue.** A queue re-checks pull requests against the
merged result without anybody doing it by hand, and is worth having for other reasons. It does not
remove the conflict: each entry would still be reconciled by a person before the queue could take it.

**Rejected: a union merge for the one file.** Git can be told to keep both sides of a conflicting
hunk, which is exactly the resolution used every time. The host that performs the merge does not
honour that setting (unverified here beyond its documented behaviour), so it would work on a laptop
and not where the merge happens.

**Rejected: a committed index, regenerated on conflict.** It keeps a readable list in the repository.
It also keeps a file every decision changes, and "regenerate it" is still a step somebody has to do
by hand between two builds.

**Undo cost.** Low. The entries can be concatenated back in number order with one command, and the
checks are one test. What would be lost by undoing it is the links that now point at one decision
rather than at a 2,500-line page.

**Impact.** Operations: two pull requests that each record a decision no longer block one another, and
a reader following a citation opens one page. What it does not cover — pull requests still conflict
when they change the same code or the same document, a number is still chosen by hand and two authors
can still reach for the same one, which now fails as a conflict rather than as a duplicate; and the
history of an entry written before this lives in the old file's log, not its own.
