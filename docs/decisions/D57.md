# D57 — Everything a release page carries is built before the release vouches for anything

**Date.** 2026-11-12. **Issue.** [#253](https://github.com/ensera-ai/taisce/issues/253).

**Why it was open.** A release was verified from a machine outside its workflow, with the commands
`SECURITY.md` gives. Every artifact verified except one: the chart package on the release page had no
provenance and no line in the checksums file. Nothing was wrong with the file. It was packaged after
the checksums were written and after the provenance step ran, into the directory the page is later
filled from by a glob — so it was published beside both and covered by neither.

**What is protected, and from whom.** Whoever installs from a file downloaded off a release page,
from that file being replaced after publication or produced by something other than the release.
The registry copy of the chart was signed all along; the page copy was the one artifact of a release
whose claim is that each artifact can be checked.

**Decided.**
- **The chart is packaged with the binaries, before the checksums file and the provenance step.**
  Packaging needs nothing a later step produces. The check that the chart asks for an image this run
  pushed stays where the image exists, and reads the package already built.
- **The checksums file is the last file written into that directory**, and the provenance step
  covers the same glob the page uploads.
- **Before the page is published, the release checks the directory rather than a list.** Every file
  the page will carry is in the checksums file with the sum it has now
  (`scripts/release-page-check.sh`), and every one verifies against this workflow at this tag. A file
  that arrives late fails the release instead of being published unvouched.
- **The page copy and the registry copy of the chart are compared**, because a reader who checked
  one assumes they checked the other.

**Rejected: a second provenance step after the chart is packaged, and its line appended to the
checksums file.** It closes this instance and keeps the shape that produced it: a directory that
goes on gaining files after the moment the release vouched for its contents. The next file added
late would be the same defect.

**Rejected: not uploading the chart package to the page.** The registry copy is signed, so the page
would carry nothing unverifiable. It would also take away the only copy that needs no registry
client, from the reader installing into a network that reaches a release page and not a registry.
An artifact is cheaper to vouch for than to withdraw.

**Rejected: documenting how to compare the page copy with the registry copy.** A reader should not
need a second download and a second tool to learn whether the first download is the release's.

**What it does not cover.**
- **Release pages published before this.** Their chart package has no provenance and no checksum
  line, and tags are immutable, so it never will. The registry copy of the same version is signed,
  and the two can be compared by digest.
- **Origin, from the checksums file alone.** It vouches for bytes. A page whose files and checksums
  file were replaced together still agrees with itself; provenance is what ties a file to the run.
- **A maintainer who controls the repository, the workflow and the registry together**, as
  `SECURITY.md` already says of every control here.

**Proof.** `TestNothingReachesAReleasePageWithoutALineInTheChecksumsFile` runs the check against
directories built wrong in each way: a file added late, a file changed, a name that extends a listed
one, a checksums file missing or empty. `TestEverythingOnTheReleasePageIsBuiltBeforeItIsVouchedFor`
holds the order in the workflow, so a wrong order fails a pull request and not a release. The
provenance of a real chart package can only be shown by the next release, whose own verification
step now requires it.

**Undo cost.** Low. It is the order of steps in one workflow and one script; no published artifact
changes shape, and the page gains a line in a file it already carried.

**Impact.**
- *Security.* The chart package on a release page can be checked the way a binary can.
- *Operations.* A release that would publish an unvouched file now stops before its page exists,
  after its images and chart are pushed. Tags do not move, so the recovery is a patch release.
