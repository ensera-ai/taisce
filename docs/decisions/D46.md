# D46 — Generation calls are counted and a cut reply is refused whole; the ceiling is the operator's

**Date.** 2026-11-11. **Issue.** [#221](https://github.com/ensera-ai/taisce/issues/221).

**Why it was open.** A generation request stated no limit on what the model could write back, the
text that decides how long a reply is was written by somebody else, and nothing counted what was
spent — an operator on a metered provider learned what formation cost from the invoice. The issue
asked for a ceiling on every call and a count of tokens.

Building the ceiling turned up two things that decide its shape.

*Measured, 2026-11-11.* A model that reasons before it answers spends the output allowance on its
reasoning. Asked for a single word under a ceiling of 64 tokens, one such model returned an empty
reply with a finish reason of `length` and reported 64 completion tokens. So a ceiling is not a bound
on the answer alone, and the number that suits one model returns nothing at all from another.

*Read from the code.* A reply that stops at a limit is sometimes still well-formed. The three callers
parsed whatever came back, so a reply cut by a provider's own limit, at a point where the fragment
happened to parse, was used: half of a message's claims stored and the message marked formed, with
nothing afterwards able to tell that from a message that asserted half as much.

**Decided.**
- **A reply that was cut is refused whole**, for all three purposes, whichever limit cut it — the
  operator's or the provider's. It is a failed attempt: the turn is tried again and parks if it is cut
  every time. The refusal says which limit it was, because the remedy differs.
- **Every generation call is counted, by purpose**: calls made, tokens sent and written where the
  provider said, calls the provider said nothing about, and replies cut. Unknown is counted as
  unknown. A provider that reports no usage is not a provider whose calls were free, and a reader
  adding up tokens has to be able to see how much of the picture is missing.
- **A cut reply is counted with what it cost.** It was paid for, and a ceiling that hid its own cost
  would make raising it look free.
- **No ceiling is stated unless the operator states one**, with `TAISCE_INFERENCE_MAX_OUTPUT_TOKENS`.
  A value that cannot be read fails startup rather than being ignored.
- **The counts are the way to choose it.** Watch what the model writes, set a ceiling well above it,
  and watch the count of cut replies stay at zero.

**Rejected: a default ceiling in each prompt file.** It is what the issue asked for and it was built
first, at 4096 tokens. It bounds spend with no action from anybody. It was withdrawn on the
measurement above: on a reasoning model an unmeasured default fails every turn rather than a few, on
the deployment of whoever did not know to change it. And a ceiling in a prompt file is a change to
that file, which rule 14 says does not land without its regression corpus — and the corpus could not
be completed against the one model available, at over a minute a call.

**Rejected: a ceiling derived from the size of the message.** One token of output per byte of input
is generous for an extraction, which quotes what it read. It does not survive the same measurement:
reasoning is not proportional to the input, and a provider with a fixed maximum refuses a request
that asks for more than it allows.

**Rejected: using whatever a cut reply could be parsed into.** It is the previous behaviour, and it
forms more turns. The turns it forms that way are the ones with something missing.

**Rejected: treating a cut reply as permanent and parking the turn at once.** A cut is usually
deterministic, so retrying mostly repeats it. Not always — providers vary a reply at temperature
zero, which the extraction corpus records — and a turn parked on its first attempt is one an operator
has to release by hand after raising the ceiling.

**Undo cost.** Low. The refusal is one check, the counts are one callback, and the setting is one
variable. The series names are the part somebody will have written a rule against.

**Impact.** Cost: what generation spends can be read, by purpose, without a provider's console —
where the provider reports it. Security: text written by somebody else no longer decides, unseen,
how much a call costs; it still decides it, up to the provider's limit, on any deployment that has
not set a ceiling. That is what this does not cover, and it is the part of the issue left open.
Operations: a deployment whose provider was silently cutting replies now sees failed attempts where
it saw formed turns, which is the correct reading and will look like a regression. Performance: one
callback per generation call, and nothing on any request's path.
