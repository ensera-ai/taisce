{{ if .Values.manage.enabled }}
Mint the first ones yourself. The output is streamed to your terminal and to no log:
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "taisce.name" . }}-manage -- /taisce operator issue <name>
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "taisce.name" . }}-manage -- /taisce credential issue <name> -project {{ .Values.project }} -access read_write

The second is the project owner's, so it is asked for with read_write: it is the one that can erase.
Leave -access off for a key an agent holds, which writes memory and cannot destroy it.

The operator token stops working after 90 days and says when; minting its replacement needs this
same command and no token. Say -no-expiry for one that never ends, or -lifetime-days <n>.

Each token is shown once, to you: only digests are stored, so a lost one is replaced by minting another, with
the same two commands. Minting does not revoke what was lost: /taisce credential list names what
exists and /taisce credential revoke <id> closes it.
{{- else }}
Nothing in this deployment can mint one: the management surface holds the administrative connection
and it is disabled. Enable it, mint, then disable it again:
  helm upgrade {{ .Release.Name }} <chart> --reuse-values --set manage.enabled=true
{{- end }}

A backup nobody has restored from is a hope. Rehearse a restore into a second cluster before you
depend on this one. A restore also brings back everything erased since the backup was taken, and
nothing here erases it again.

THIS DEPLOYMENT HAS NO BACKUP. postgresql.cnpg.backup.acknowledgedNone is true, so it holds only
what its {{ .Values.postgresql.cnpg.instances }} database instance(s) hold. An erasure of the wrong subject, a failed migration, a dropped
schema or an uninstall cannot be recovered from. To change that, create an ObjectStore and set
postgresql.cnpg.backup.objectStore to its name.
