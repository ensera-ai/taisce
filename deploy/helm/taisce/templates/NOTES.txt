The first credentials are printed once, by the bootstrap Job of the revision that minted them:
  kubectl -n {{ .Release.Namespace }} logs job/{{ include "taisce.name" . }}-bootstrap-{{ .Release.Revision }} | grep token

Copy them out now. That log is the only copy — only digests are stored — and the next upgrade
deletes this Job and its log with it. A later revision's Job finds the instance already reachable
and mints nothing, so it has no token to print.

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "taisce.name" . }}-manage -- /taisce operator issue replacement
  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "taisce.name" . }}-manage -- /taisce credential issue replacement -project {{ .Values.project }}

Minting does not revoke what was lost: /taisce credential list names what exists and
/taisce credential revoke <id> closes it.
